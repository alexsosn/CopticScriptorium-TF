# Cross-consumer output infrastructure migration (Coptic #196)

## Evidence examined before implementation (2026-11-15)

- The original tf-build project goal is actual duplication removal across *multiple* Text-Fabric converters, not indefinite standalone helper hardening. ORAEC-TF currently calls tf-build source/publication; IIP-TF adoption is being tested separately. Coptic is a third independent conversion implementation.
- Current `copticscriptorium_tf/agora.py::materialize` manually checks an existing output root (non-symlink directory, empty) before TT conversion. The released `tf_build.agora.prepare_agora_output` does exactly this and returns a canonical root. Its `AgoraOutputError` derives from ValueError, consistent with Coptic's original failures. We should discard the returned canonical root to preserve Coptic's existing relative returned output path.
- Current `copticscriptorium_tf/_atomic.py` is a near-line-by-line copy of `tf_build._atomic.py` at published immutable tag `v0.1.0rc1`: Linux `renameat2(RENAME_NOREPLACE)`, macOS `renamex_np(RENAME_EXCL)`, Windows nonreplacing `os.rename`, FileExistsError for occupied targets and OSError for unsupported/failed operations. The shared **public** endpoint is `tf_build.publication.publish_path_no_clobber`, already used by ORAEC-TF. Coptic `writer.py` and `converter.py` use the local publisher for TF directory and summary file publication, respectively.
- `tests/test_issue15_writer_integration.py` has real Fabric.reload/native graph assertions and adversarial existing empty directory, file, symlink and race/no-clobber cases. It imports `copticscriptorium_tf._atomic` and monkeypatches its `sys.platform`/`os.rename` in legacy platform tests; removing this module outright would break that fixture even though downstream production import is private. A tiny re-export shim with explicit `os` and `sys` module aliases preserves that test contract without maintaining copied atomic logic.
- `tests/test_issue50_atomic_summary.py` checks write-failure cleanup and no-clobber summary publication; `tests/test_issue17_agora_materializer.py` runs actual directory-plus-zipped TT → native TF, Fabric.load, unchanged TF file bytes relative to direct conversion, user-local unversioned source, and no network. The workflow `.github/workflows/issue17-agora.yml` includes a pinned real Gospel of Thomas input/host smoke; `issue177-agent-user-smoke.yml` exercises installed-wheel user-facing paths.
- `pyproject.toml` currently requires Python >=3.12 and Text-Fabric 13.1.0. `tf-build` at released GitHub tag `v0.1.0rc1` requires Python >=3.11 and Text-Fabric >=13.1,<14. The release published wheel `tf_build-0.1.0rc1-py3-none-any.whl` SHA-256 is `dff2a14c0299422b4716217d04e6d43b47e714f4dacdb21d9939292051e82c9a`. The release workflow publishes **only GitHub Release assets**, so a plain `tf-build==0.1.0rc1` index requirement is not sufficient. Use a SHA256-locked PEP508 GitHub wheel URL, preserving normal `pip install .` and existing CI install commands. `0.1.0rc2` is not published. A future PyPI publication may need metadata changes.

## Focused plan, tests-first

1. RED-before-production assertions inside existing `tests/test_issue17_agora_materializer.py`: require real adapter preflight delegation before source parsing (via monkeypatched imported function), require both writer and summary publisher to have their real implementation from `tf_build._atomic` rather than copied local module, and require the exact SHA256-verified URL in package metadata. These fail on unchanged current code.
2. Implement by importing the published `prepare_agora_output` in the Agora adapter and replacing its two checks with a single call. Replace **only** the local low-level `_atomic.py` body with a compatibility re-export from `tf_build.publication`, retaining the explicit `os` and `sys` module aliases so existing platform-branch monkeypatch contracts continue to address the same global objects. Leave writer/converter call-site aliases unchanged; they now resolve to the shared actual function. No graph/writer/model/release logic change.
3. Add the hash-locked release wheel URL as runtime dependency; document the integration and distribution caveat. Run the full exact-head CI and true pinned TT/host-installed-user smokes.
4. Independent adversarial review: compare exact tagged shared source with original local source; re-check simulated competing destinations and platform emulation, output staging byte parity, symlink/nonempty paths, missing source and user-local provenance; verify no input source is rewritten, new diagnostics remain ValueError-compatible, and installed distribution resolves the declared GitHub wheel.

## Non-goals

No new public shared API, replacement build workspace, graph/slot ontology change, Unicode/TT normalization, CoNLL-U semantics, corpus release or Agora marketplace registration.

## Exact-head CI discovery: legacy job installation bypasses project metadata

Actual PR head `73c392ce1c11007dacbaf33563d551f9ac8de260` successfully fixed Hatch's direct-reference metadata gate, but [issue15-writer job 132622765996](https://github.com/alexsosn/CopticScriptorium-TF/actions/runs/43652147302) failed: `ModuleNotFoundError: No module named 'tf_build'` for three real native writer tests. `.github/workflows/issue15-writer.yml` installs only `text-fabric==13.1.0` (not the Coptic project); the original copied internal publisher had no dependency to install. Similar legacy workflows in the 35-workflow collection use the same incomplete environment setup. This is a **real** post-migration CI failure, independent of parsing or corpus output. Replacing the package dependency with a source-code fallback would defeat the consolidation goal.

Scope addition: for native conversion workflows that currently use the exact single command `python -m pip install 'text-fabric==13.1.0'`, switch it to `python -m pip install .`. Project metadata pins both TF 13.1.0 and the hash-verified published tf-build wheel, so this makes the tests execute against an **installed consumer package with its actual declared dependencies** rather than an accidental checkout-only import. This is a targeted workflow installation correction, not a change to scientific semantics. Keep the checked-out exact SHA, CI script commands and all real source pins. Add a regression test for the workflow dependency gate; rerun all affected exact-head workflows and independent review. Workflows that intentionally build a clean wheel / already install the project stay unchanged.
