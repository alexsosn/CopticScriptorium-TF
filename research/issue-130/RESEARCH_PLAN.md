# Issue #130: native bilateral Coptic↔LXX inverse-query API

## Actual repository research
CopticScriptorium-TF main already publishes **two additive native TF modules** over separately owned Text-Fabric warps: source Coptic word features `coptic_lxx_ref_id`, `coptic_lxx_ref_status`; pinned CenterBLC/LXX Greek verse feature `coptic_lxx_ref_id`. The **legacy** `lxx_modules.py` additionally emits `coptic_lxx_source_span_count`; the current source-locked `lxx_module.py` / streaming generator **does not** emit that count. Requiring it would reject our own fingerprint-verified native modules. The edition-qualified string `CenterBLC/LXX:1935:<book>:<chapter>:<verse>` is the **only** cross-warp key; integer node IDs must never cross warp boundaries. The production source/Greek module authors validate byte-pinned parent corpora and map source reference candidates, not textual equivalence. No researcher-facing inverse query exists in `examples/query_cookbook.py` as of this ticket.
