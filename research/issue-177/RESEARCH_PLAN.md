## User journey / RED-first / direct real CI
1. RED-first `tests/test_issue177_agent_smoke.py`: demand a dedicated bounded job with *exact pinned physical* Thomas+Pistis source paths, public wheel installation outside checkout and real user commands, plus test for absence of converter-internal imports. Before implementation, test fails on missing files.
2. Implementation: CI checks out only the two immutable upstream TT files, asserts Git revision and original Thomas file byte length, builds wheel once, installs into fresh venv, executes the new smoke from scratch outside the repository directory. No plugin implementation, no new semantic TF classes.
3. The agent-run script calls documented installed CLI with physical TT root, explicit upstream repository/pin and a fresh summary outside output; verifies the generated `otype/oslots/otext`, direct Fabric reload, section lookup by physical ID, lemma inverse hit, dependency edge and original text format. Then calls installed `copticscriptorium-tf-web --check` (without binding a network server).
4. Negative journey: empty source root via the same installed CLI must fail with actionable `no supported TT source records`; no partial TF directory may be published. Only minimal JSON operational output with node counts, hashes and success booleans is logged; no raw/derived copyrighted corpus artifacts uploaded.
5. Review behavior as a *new user* after the runner: examine actual commands and assertions in job log, not just exit code; document any CLI/docs friction in the issue. On failure add RED case, repair minimal bug, re-run and do a logically separate adversarial review of exact code + source logs before merge.
6. This proves installed direct local-source and web-app path only. The earlier Agora full registered run remains separate evidence. Do not claim fully exploratory autonomous UI browsing/Context-Fabric agent testing beyond observed results, and keep #177 open if that requirement remains unmet.

## Bounds
- Separate `workflow_dispatch` enabled; scope two original TT files, no unbounded original source checkout; timeout 30 minutes. Latest upstream is irrelevant; only reviewed pinned commit is used. No generated data redistribution, original source text emitted to logs, or network after handoff.

## Independent adversarial pre-review repair

The first implementation used to include raw subprocess stderr on failure in CI exceptions. Such exceptions can inadvertently echo original TT witness text. A regression contract now disallows the raw stderr slice; on failure the user journey records command name, exit code and only a short SHA256 fingerprint of stderr. The negative empty-source test checks its actual error phrase internally without printing it. Browser `--check` is only a non-serving setup test, not graphical UI exploration.
