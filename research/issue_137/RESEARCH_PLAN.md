# Issue #137 — graph object storage census before representation optimization

## Research (real pinned workload, not a speculative speedup)
- Exact `CopticScriptorium/corpora@3ac067f1709a0012daf39ea8da2fac79980176a5`, Python 3.12 + Text-Fabric 13.1.0. Full TT source: 2,628 physical records, 2,394,354 word slots, >4.1m non-slot nodes including newer source annotation wrapper features. The converter already provides source-free per-phase RSS/peak timings, [#109](https://github.com/alexsosn/CopticScriptorium-TF/issues/109) and merged PR #139.
- Latest exact-source graph instrumentation: parse live ~3,351 MiB, post-graph ~6,451 MiB, post-release models ~6,411 MiB, writer max ~7,564 MiB. The +3.1GiB live graph increase motivates inspecting GraphNode/GraphSlot/GraphEdge containers and slot_ranges rather than blindly interning source_record_id (already one per document). CoNLL-U augmentation is a separate workload and MUST NOT be mistaken for equivalent TT-only A/B evidence.
- Existing `_graph_core.py` has immutable `slots=True` dataclass objects, `GraphNode.slot_ranges` nested tuple loci. These millions of objects are plausible memory contributors, but shallow `sys.getsizeof` is not allocation tracing or RSS.

## Plan — research / RED / implement / test / independent review
1. Commit RED-first synthetic tests before measurement utility. Require accurate object counts, node/edge type distributions, single vs multi vs empty loci, segment and covered-slot counts, bounded shallow graph-object and locus-tuple **estimates**, rejection of malformed range tuples, and no raw source field values in JSON.
2. Implement an **opt-in**, read-only `graph_storage_census(graph)` of the existing built graph, one pass, O(1) histogram memory independent of corpus size. No global interning, caching millions of ID/range objects, or graph mutation. Report shallow bytes explicitly as **non-unique upper bounds** for nested tuples, excluding referent strings/other Python containers and allocator overhead; never present them as process RSS.
3. Add an optional graph probe to the converter only when explicitly supplied. In a 2-document TT native TF round-trip, assert all per-file `.tf` SHA256 hashes are exactly the same with and without profiling. Preserve API defaults and errors.
4. Add `--profile-graph` to the **existing** full converter smoke, composable with existing `--profile-memory`; keep profiling strictly opt-in. Route this research branch through the already-present pinned full NT native TF / 2,747 SBL source / 2,362-candidate, 376-ambiguous, 8-unresolved, 1-edition-unavailable, 944-Greek-verse bilateral reload acceptance workflow, with no new redundant full runner. Upload only source-free JSON, time and RSS.
5. Inspect real count/type/range distribution and **independently adversarially review** candidate representation and actual source/native TF parity. If full output or parent corpus differs, reject/repair. Do not claim the <5GiB performance goal is achieved by a measurement utility.
6. Select a separate **coherent** optimization from evidence (e.g. compact GraphNode locus representation vs lifetime-management) and require comparable baseline/candidate runs before optimization merge. Keep `#137`/`#109` open until actual memory reduction is demonstrated, not closed after instrumentation.

## Non-goals
Neither Greek NT parent nor restricted Coptic source content is modified or redistributed. Source SBL/Greek NT candidate addresses remain governed by #117 and unchanged. No Coptic word-level or historical text alignment is inferred.
