# Issue #70 — Coptic verse → CenterBLC/LXX reference resolution

## Research
- DSS ↔ BHSA prototype: [ETCBC/dss/alignment/README.md](https://github.com/ETCBC/dss/blob/master/alignment/README.md) partitions by book/chapter/verse then uses longest matching consonantal word subsequences, morphology and matres lectionis correction (1QIsaᵃ: 70% predicted + 11% possibilities). It does *not* supply cross-warp TF edges, and the separate DSS `parallels/tf/sim.tf` is only DSS-internal line similarity.
- Pin `CenterBLC/LXX@f32a98eddf7eb239aa73ab863d70381e416d5076`, tag v1.0.1 / TF 1935, as in [CATSS-TF/src/catss_tf/lxx_schema.py](https://github.com/alexsosn/CATSS-TF/blob/main/src/catss_tf/lxx_schema.py); parent word slots 623,693, verse nodes 30,371, native `book/chapter/verse` section hierarchy and subverse nodes. Existing CATSS-TF modules project shared CATSS IDs onto BHSA and LXX native nodes, without cross-warp edges.
- Critical CATSS-TF provider detail: `TextFabricLxxProvider.get_span(book,chapter,verse,subverse=None)` **filters out all words whose `subverse` feature is nonempty**, and returns None if no unsplit words remain. Therefore its default null return is **not** a reliable proof that an LXX verse node is absent. Use a validated actual parent API `T.nodeFromSection((book, chapter, verse))` for reference existence, and reserve `get_span` for token/subverse mapping after handling split verses explicitly.
- Actual pinned Coptic sources: `sahidic.ruth/Ruth_02.tt` gives `verse_n=1`, `verse_vid=Ruth 2:1`, `vid_n=urn:cts:copticLit:ot.ruth.copto_edt:2.1`; `sahidic.jonah/Jonah_02.tt` has 11 `verse_n` and *no* additional CTS/verse_vid; `bohairic-habakkuk/Habakkuk_02.tt` has 20 `verse_n`, `meta book=Habakkuk,chapter=02`. Upstream warns these may use different versification from canonical LXX even when labels match. Issue #69 preserves the raw markers in native Coptic word features.
